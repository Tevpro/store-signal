# MV3 /v1 integration (not a released checker)

From repo root: `npm ci --ignore-scripts`, then `npm run lint --prefix apps/extension`, `npm run typecheck --prefix apps/extension`, `npm test --prefix apps/extension`, `npm run build --prefix apps/extension`, `node --import tsx apps/extension/tests/worker-smoke.ts`. Load unpacked `apps/extension/dist` in Chrome/Chromium (Developer mode). Build output is ignored by Git. There is no service worker/content script, tabs/history permission, store-page host permission or automatic request. Popup open reads only saved endpoint settings. On explicit click the browser requests access to the chosen API origin; permission denial stops before tab lookup and network.

Enter an operator-provided hosted HTTPS `/v1/` URL or a self-hosted HTTPS `/v1/` URL. HTTP is permitted for loopback development only. Only public store origin is sent in `POST /v1/checks`; no path, query, fragment, credentials, HTML, or cookies. `checking` is polled by server-provided ID on the same endpoint with bounded attempts; quota and unsupported responses stop polling. UI parses the versioned `/v1` response and escapes source links/labels. The current backend has no licensed providers or durable dispatcher ready for public use; don't infer a real safety verdict from the synthetic limited/insufficient fixtures.

The headed browser probe now proves the toolbar popup against both local APIs: after `npm install --no-save --package-lock=false --ignore-scripts playwright-core` and the extension build, start a private `Xvfb :94 -screen 0 1280x900x24 -nolisten tcp`, then run `DISPLAY=:94 CHROMIUM_HEADED=1 CHROMIUM_PATH=/path/to/chrome node --import tsx apps/extension/tests/browser-integration.mjs` from repo root. `tests/toolbar-ui.py` clicks the ordinary Chromium Extensions menu and OCR-verifies the StoreSignal entry; the probe attaches CDP only to the popup target _after_ toolbar launch (Playwright `context.pages()` excludes browser-action popups). Browser optional-host permission is granted only through `tests/permission-ui.py`, which OCR-verifies the visible StoreSignal loopback request before clicking Allow. Chromium closes the action popup during the native prompt; reopen it through the toolbar and explicitly click Check again. No pregrant, `chrome.permissions` injection, direct popup tab, CDP permission API or browser flag bypass. The probe asserts `https://example.com/cart?secret=never-send#fragment` remains the selected store tab; zero passive requests on popup open/reopen; the on-screen Check click causes only `{"origin":"https://example.com"}` in each POST, without cookies, path or HTML; real Node/SQLite and Wrangler-local Worker/D1 synthetic ingress each return checking → complete → cached. The Worker completion route is test-only and called outside the shopper proxy. The log intentionally omits raw status grants/check IDs. This is local synthetic evidence, NOT full #16 acceptance or a production/connector claim. The product Worker remains fail-closed without trusted ingress, licensed connectors and a durable dispatcher. The extension may be reviewed in a PR, but no provider call, release or deployment is included.
